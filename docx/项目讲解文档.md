## 第 1 章　这个项目是什么

一个「标准地名地址管理系统」，业务主线是 **门牌（地名地址）的申请与审批**：

```
群众（审批网站）提交门牌申请  →  管理员（管理系统）逐级审核  →  审核结果回显给群众查询
```

它由两个前端门户 + 一个后端组成：

- **审批网站（用户端 / Portal）**：面向群众。看政策公告、提交门牌申请/补发、查询自己的申请进度、排查门牌。
- **标准地名地址管理系统（管理端 / Admin）**：面向管理员。审批申请、管理门牌、管理行政区划、配置审批流程、管理用户与权限、看统计与日志、管理审批网站的内容等。
- **后端（Spring Boot）**：提供 REST 接口，连接 MySQL 数据库。

## 第 3 章　整体架构与一次请求的完整旅程

### 3.1 三层 + 分包结构（后端）

后端采用经典的 **Controller → Service → Mapper** 三层：

```
HTTP 请求
   │
   ▼
[Controller]  只做“收参数 / 调 Service / 包装 Result 返回”，不写业务逻辑
   │
   ▼
[Service(接口) + ServiceImpl(实现)]  业务逻辑、事务、跨表编排都在这里
   │
   ▼
[Mapper]  继承 MyBatis-Plus 的 BaseMapper，负责和数据库表打交道
   │
   ▼
[MySQL 数据库]
```

配套还有：
- `entity/`：和数据库表一一对应的 Java 类（一个类 = 一张表）。
- `dto/`：数据传输对象。`Result` 是统一返回壳；`XxxDTO` 是接收前端入参；`LoginVO` 是返回给前端的视图对象。
- `config/`：全局配置（跨域、MyBatis-Plus、静态资源映射）。
- `util/`：工具类（如本次新增的 `ValidatorUtil` 校验工具）。

### 3.2 统一返回格式 `Result<T>`

后端几乎所有接口都返回 `Result<T>`：

```json
{ "code": 200, "msg": "操作成功", "data": { ... } }
```

- `code=200` 成功，`code=500` 失败（`msg` 是失败原因）。
- 前端统一用一个 `unwrap(res)` 取 `res.data.data` 拿真正的数据，用 `res.data.code !== 200` 判断失败。

### 3.3 前后端如何连起来（关键！也是你 404 问题的根源知识点）

- 后端跑在 `http://localhost:8080`。
- 前端开发服务器（Vite）跑在 `http://localhost:5173`。
- 两个端口不同 = 跨域。本项目用两种方式打通：
  1. **Vite 代理**（`vite.config.js`）：前端代码里写相对路径 `/api/...`，Vite 把它转发到 `http://localhost:8080/api/...`。所以**只有以 `/api` 开头的请求**才走代理。
  2. **后端 CORS**（`CorsConfig.java`）：允许跨域，于是前端也可以直接写绝对地址 `http://localhost:8080/...`。项目里 `/news`、`/about`、`/user/apply` 这些**不以 `/api` 开头**的接口，前端就直接写了 `http://localhost:8080` 绝对地址（因为它们不被 Vite 代理）。

> 记住这条：前端请求要么写 `/api/xxx`（走代理），要么写 `http://localhost:8080/xxx`（走 CORS）。两者都依赖**后端真的有这个接口且已启动**——否则就是 404。

### 3.4 登录态与权限

- 登录成功后端返回 `LoginVO{ id, phone, realName, areaId, role }`，前端用 `utils/auth.js` 存进 `localStorage`。
- `role` 三种：`coreAdmin`（核心管理员）> `normalAdmin`（普通管理员）> `user`（普通群众）。
- 前端路由守卫（`router/index.js`）：`/admin/**` 必须是管理员；用户端除主页外需登录。
- 后端按 `userId` 查角色做服务端鉴权（如“只有核心管理员能配置审批流程”）。

### 3.5 一次完整请求示例（群众提交门牌申请）

以“群众提交新门牌申请”为例，看数据怎么从前端流到数据库：

1. 群众在 `ApplySubmit.vue` 填表，点“提交申请”。
2. 前端 `submitApply()` 先做校验（含本次新增的**手机号 11 位**校验），再 `axios.post('http://localhost:8080/user/apply/submit', form)`。
3. 后端 `ApplyUserController.submit()` 接收 `ApplyForm`，调用 `ValidatorUtil.requireValidPhone()` 兜底校验手机号，生成申请号 `AP+时间戳`，状态置 `PENDING`，调 `applyFormService.save()`。
4. `ApplyFormServiceImpl`（继承 MyBatis-Plus 的 `ServiceImpl`）的 `save()` 把数据写进 `apply_form` 表。
5. 返回 `Result.success("提交成功")` → 前端弹“提交成功”。

之后管理员审批：`ApplyAdminController.audit()` → `ApplyAuditServiceImpl.audit()` 逐级流转，最后一级通过时调 `enterHouse()` 把门牌写进 `house_info`（含本次修复的 geometry 逻辑），群众即可在“门牌排查”里查到。

## 第 5 章　后端文件逐个讲（每个文件内部怎么实现）

### 5.0 启动与配置

- **`SpptApplication.java`** — 启动类。`@SpringBootApplication` 开启自动配置；`@MapperScan("com.example.sppt.mapper")` 告诉 MyBatis-Plus 去哪儿找 Mapper 接口。`main` 里 `SpringApplication.run(...)` 起服务。
- **`config/CorsConfig.java`** — 全局跨域配置。`addCorsMappings` 对 `/**` 允许所有来源、允许带 cookie、允许 GET/POST/PUT/DELETE/OPTIONS。让前端 `http://localhost:5173` 能直接访问后端 `:8080`。
- **`config/MybatisPlusConfig.java`** — MyBatis-Plus 配置，主要注册**分页插件**（`PaginationInnerInterceptor`），让 `page()` 方法的分页生效（用户管理、日志分页等依赖它）。
- **`config/WebMvcConfig.java`**（本次新增）— **静态资源映射**。把磁盘上的上传目录（`file.upload-dir`，默认 `./uploads`）映射成 URL 路径 `/uploads/**`。这样上传的图片能直接通过 `http://localhost:8080/uploads/...` 访问。**问题 4 图片显示依赖它。**
- **`resources/application.yml`** — 配置文件：数据库连接、MyBatis-Plus 选项、**文件上传大小限制**（本次加的 `multipart`）、**上传目录** `file.upload-dir`（本次加）。

### 5.1 dto（数据传输对象）

- **`Result.java`** — 统一返回壳 `{code,msg,data}`，提供 `success(data)` 和 `fail(msg)` 两个静态方法。**全后端的接口出口都是它。**
- **`LoginDTO.java`** — 接收登录入参 `{phone,password}`。
- **`RegisterDTO.java`** — 接收注册入参 `{phone,password,realName,areaId}`。
- **`LoginVO.java`** — 登录成功返回给前端 `{id,phone,realName,areaId,role}`（不含密码）。
- **`AuditDTO.java`** — 审批入参 `{applyId,auditUserId,status(APPROVED/REJECTED),remark}`。
- **`ApplyProcessConfigDTO.java`** — 审批流程配置入参：申请类型、级数、每级审核人 id 列表、操作人 id（鉴权）。
- **`RolePermDTO.java`** — 角色授权入参 `{roleId, permIds[]}`。

### 5.2 entity（表映射）

每个类都是 `@Data`（Lombok 生成 getter/setter）+ `@TableName`。字段含义见第 4 章表与代码注释。要点：
- `HouseInfo.geometry` 是 **String**，存 WKT 文本 `POINT(经度 纬度)`（**问题 1 的关键**：不要用数据库的 POINT 二进制类型，否则读进 String 会乱码）。
- `News.coverImage`（本次新增，`@TableField("cover_image")`）存图片**访问路径**字符串（不是图片二进制）。

### 5.3 mapper（数据访问）

绝大多数 Mapper 只是 `interface XxxMapper extends BaseMapper<实体> {}`，空接口就自动拥有全部 CRUD。少数写了自定义 SQL（用 `@Select` 注解，无 XML）：
- **`SysUserMapper.selectAdminUsers()`** — 三表联查，取出所有管理员（角色是 coreAdmin/normalAdmin）。
- **`SysUserRoleMapper.selectRoleNamesByUserId()`** — 查某用户的全部角色名（登录后判定身份用）。
- **`SysRolePermMapper.selectPermIdsByRoleId()`** — 查某角色已分配的权限 id。

### 5.4 service / service.impl（业务逻辑）

约定：`XxxService` 是接口，`XxxServiceImpl` 是实现；多数实现 `extends ServiceImpl<XxxMapper, 实体>` 从而白拿 MyBatis-Plus 的 `list/save/getById/page/count/remove...`。

- **`AuthService / AuthServiceImpl`** — 登录注册。`register()`：校验手机号唯一+**格式（本次加 ValidatorUtil 兜底）**、写 `sys_user`、绑定 `user` 角色、记日志。`login()`：按手机号+密码查用户，取最高角色，组装 `LoginVO`。
- **`SysUserService / Impl`** — 用户管理。`getAdminUsers()` 取管理员；`pageUsersWithRole()` 分页查用户并附角色名；`setAdmin()` 设/取消管理员（改 `sys_user_role`）；`changePassword()` 改密码（**本次加密码格式校验**）；`updateProfile()` 改资料（**本次加手机号格式校验**）。
- **`SysUserRoleService / Impl`** — 用户角色关联。`hasRole()` 判断某用户是否某角色；`bindRole()` 绑定；`getRoleNamesByUserId()` 查角色名。
- **`SysRoleService / Impl`** — 角色。`getOrCreateByName()` 取或建角色。
- **`SysPermissionService / Impl`** — 权限（菜单/按钮）的读取。
- **`SysRolePermService / Impl`** — 角色授权。`assignPerms()` 先清空该角色权限再批量写入（事务）；`getPermIdsByRoleId()` 查已选权限。
- **`SysAreaService / Impl`** — 行政区划的读取（前端级联、地图、统计都依赖 `list()`）。
- **`ApplyFormService / Impl`** — 申请单的基础 CRUD（提交、我的申请列表都走它）。
- **`ApplyApprovalService / Impl`** — 审批记录的基础 CRUD（每审一次写一条）。
- **`ApplyProcessConfigService / Impl`** — 审批流程配置。`getProcessConfigByType()`：查不到就**按申请类型生成默认流程**（new 默认 3 级、reissue 默认 1 级，从管理员里轮流分配）；`saveProcessConfigByType()`：**仅核心管理员**可保存，先删旧配置再逐级写入（事务）。
- **`ApplyAuditService / Impl`** — **审批的核心编排**（最复杂的业务）。
  - `listPending()/listHandled()`：按“责任过滤”列出该管理员该看的申请。
  - `audit()`：写一条审批记录；驳回 → 直接 `REJECTED`；通过 → 判断本级是否满足 ONE/ALL 策略，满足则进入下一级，最后一级通过则 `APPROVED` 并调 `enterHouse()`。
  - `enterHouse()`：通过后生成门牌。新申请在街道内自增三位号、拼 `house_code`，**用街道的经纬度拼 WKT 写入 `geometry`（问题 1 修复点）**；补发则复用原门牌号。
  - `progress()`：返回当前级别/总级别/各级记录，供前端展示进度。
- **`HouseService / Impl`** — 门牌 CRUD + `nextHouseNumber()`（街道内下一个可用三位号）+ `getByHouseCode()`。
- **`HouseInfoService / Impl`** — 门牌的另一套基础读写（“门牌排查”页 `/house/**` 用）。
- **`HousePdfService / Impl`** — 用 iText5 + 中文字体把单个门牌信息导出成 PDF 字节流。
- **`NewsService / Impl`** — 政策/公告。各种按类型/城市的查询；`saveNews()/updateNews()` 写入前做**禁用词校验**（命中则抛异常拒绝），整实体保存因此**自动带上 `cover_image`（问题 4）**。
- **`PortalAboutService / Impl`** — “关于我们”读写，`getByAreaId()` 按区域查。
- **`SysBannedWordService / Impl`** — 禁用词增删查 + `findHit()`（检测标题/正文是否命中禁用词）。
- **`SysLogService / Impl`** — `record()` 写一条操作日志（失败不影响主流程，只告警）；`page()` 分页查日志。
- **`SysHelpService / Impl`** — 帮助文档读取。
- **`StatsService / Impl`** — 统计聚合：概览数字、按类型/区域的门牌数、按状态的申请数（用 Java Stream 分组计数）。

### 5.5 util（本次新增）

- **`util/ValidatorUtil.java`** — 公共校验：`isValidPhone`（11 位纯数字）、`isValidPassword`（数字+字母、不含符号、两者都要有），以及会抛异常的 `requireValidPhone/requireValidPassword`。**问题 1 的后端兜底**，被 `AuthServiceImpl`、`SysUserServiceImpl`、`ApplyUserController` 调用。

## 第 8 章　如何运行（重要：解决你的 404）

> **你遇到的“上传失败 404 / 缓冲查询 404”，根因是后端跑的是旧的已编译代码（`target/` 里的旧 class），里面没有新接口。** 本次已删除旧 `target/`。请务必按下面**重新编译并重启**。

### 8.1 数据库
1. 建库并依次执行 `sql/` 下脚本（建表→种子→升级→修复）。本次新增两条必须执行：
   ```sql
   SOURCE sql/fix_geometry_2026_06_01.sql;        -- 修复 geometry（历史问题1）
   SOURCE sql/upgrade_news_image_2026_06_01.sql;  -- 新增 portal_news.cover_image（问题4）
   ```
2. 在 `application.yml` 改成你自己的 MySQL 账号密码。

### 8.2 后端（关键步骤）
- IntelliJ：菜单 **Build → Rebuild Project**，再运行 `SpptApplication`；
- 或命令行：`cd sppt && ./mvnw clean package && java -jar target/sppt-0.0.1-SNAPSHOT.jar`
- 验证接口已加载：浏览器打开 `http://localhost:8080/api/gis/area-summary`，能返回 JSON 即说明 `GisController` 新接口在；打开 `http://localhost:8080/test` 应返回“后端服务正常”。

### 8.3 前端
```
cd sppt-frontend
npm install      # 首次需要
npm run dev      # 启动开发服务器（默认 5173）
```
