## 任务 1：根据新数据库重写 entity 包

**改了哪些实体：**

1. **ApplyForm.java**
   - 新增 `originalHouseCode (String)`：对应新表 `original_house_code VARCHAR(50)`，补发时填原门牌号，新申请为 NULL。旧实体完全没有这个字段。
   - `houseId` 类型由 `Long` 改为 `Integer`：新表语义变了——`house_id` 不再是指向 `house_info(id)` 的外键，而是「审批通过后分配的三位门牌号」（1..999），与街道 id 拼成门牌编号。
   - 保留 `applicantName`、`houseType`、`detailAddress`（按你的选择保留，需配套执行 SQL 把列补回）。

2. **HouseInfo.java**
   - 新增 `applyNo (String)`：对应 `house_info.apply_no`（UNIQUE NOT NULL，关联 `apply_form.apply_no`）。
   - 新增 `createTime (LocalDateTime)`：对应 `house_info.create_time`。
   - **这两列此前实体里没有**，导致 MyBatis-Plus 生成的 INSERT 不包含 NOT NULL 的 `apply_no`，门牌入库/查询出错（见任务 8）。

3. **PortalAbout.java**：`areaId` 由 `String` 改为 `Integer`（新表是 `INT`，类型不符会查询/插入异常）。

4. **删除 SiteConfig.java、SysDict.java**：新数据库（数据库重制版）中没有 `site_config` / `sys_dict` 表，且全工程无任何引用，属于与库不一致的孤儿实体，予以删除。

其余实体（SysUser/SysRole/SysUserRole/SysPermission/SysRolePerm/SysArea/ApplyApproval/ApplyProcessNode/News/SysLog/SysBannedWord/SysHelp）经核对已与新表一致，未改。

## 任务 2：因数据库改变联动的前后端 + 业务流程

- 提交申请页改为用级联框选「所属街道」，把街道 id 写入 `areaId`。

### 2.2 新申请 / 补发业务流程（核心）
重写 `service/impl/ApplyAuditServiceImpl.java` 的 `enterHouse()`：

- **新申请 (new)**：
  1. 取申请人街道 `areaId`，调用 `houseService.nextHouseNumber(areaId)` 生成街道内下一个三位号；
  2. 拼 `houseCode = {街道areaId}-{NNN}`（如 `10086-001`）；
  3. 新增 `house_info`，写入 `apply_no`、`house_code`、`area_id`、`create_time`、`status=1`；
  4. 把三位号回写 `apply_form.house_id`。
- **补发 (reissue)**：
  1. 以 `apply_form.original_house_code` 在 `house_info.house_code` 中定位原门牌；
  2. 复用原门牌号，不生成新号；只把原 `house_info.status` 置 1。

旧代码用 `"MP-" + applyNo` 当门牌号、且用 `house_id` 当外键，已和新规则完全冲突，全部重写。

### 2.3 配套改动
- `HouseService` / `HouseServiceImpl`：新增 `nextHouseNumber(streetAreaId)`（扫描该街道已有 `{id}-NNN` 的最大号 +1，上限 999）与 `getByHouseCode(code)`。
- `controller/ApplyUserController.submit()`：服务端兜底生成 `apply_no`（唯一非空）；新申请清空 `originalHouseCode`、`houseId`；默认 `PENDING`。
- `views/user/ApplySubmit.vue`：补发改为提交 `originalHouseCode`（旧版只把原门牌号塞进 reason 文本，业务拿不到）；新申请用级联框选街道。
- `service/impl/HousePdfServiceImpl.java`：原本用 `apply_form.house_id = 门牌主键` 关联申请记录——语义已变，改为用 `house_info.apply_no` 关联，避免查错/查空。

## 任务 8：门牌排查取不到数据 —— 这是出什么问题了

**两个根因：**

1. **实体缺列**：`HouseInfo` 实体此前没有 `apply_no` / `create_time`，与新表不匹配，
   门牌入库的 INSERT 缺少 NOT NULL 的 `apply_no` 而失败，自然查不到数据（已在任务 1 补全实体 + SQL 补列）。

2. **前端 ref 用错（导致列表整体空白）**：`views/user/Check.vue` 里
   `const areaId = getAreaId() || 0` 是**普通常量**，但模板与过滤、`onMounted` 里却用 `areaId.value`，
   取到 `undefined`，过滤条件 `item.areaId === parseInt(undefined)` 永远不成立 → 列表被过滤为空；
   且 `onMounted` 调用了**根本不存在的** `loadList()`（实际函数名是 `loadHouse`），加载逻辑没跑。

**怎么改的**：把 `Check.vue` 重写——`areaId` 改为真正的 `ref`，接入四级级联框（不选=查全部、选到街道=按街道查），
统一 `loadList()` 命名，加 id→街道名映射展示，并对齐浅蓝 UI。
